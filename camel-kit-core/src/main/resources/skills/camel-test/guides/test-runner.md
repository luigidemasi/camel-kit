# Test Runner Guide

> **Context variables provided by master SKILL.md:**
> - `FLOW_NAME` — the flow being tested
> - `TEST_DIR` — resolved test file directory

---

## Step 6: Run Integration Tests

Use the Camel CLI test runner to execute Citrus integration tests. The `camel test run` command handles the full lifecycle: starting Testcontainers, launching the Camel integration, executing test actions, validating assertions, and tearing down.

### 6.1 Run Tests for a Specific Flow

```bash
camel test run {TEST_DIR}{FLOW_NAME}.camel.it.yaml
```

### 6.2 Run All Integration Tests in the Project

```bash
camel test run *.it.yaml
```

### 6.3 Prerequisites

- Docker must be running (Testcontainers requires it)
- Camel CLI must have the test plugin installed (`camel plugin add test`)
- Test dependencies declared in `jbang.properties` (generated by test-generation.md)

### 6.4 What Happens During Test Execution

The `camel test run` command:
1. Reads the Citrus YAML test file
2. Starts Testcontainers for declared services (Kafka, PostgreSQL, etc.)
3. Starts the Camel integration via `camel:jbang:run` action in the test
4. Executes send/receive actions against the running integration
5. Validates message content against expected values
6. Stops the Camel integration and Testcontainers
7. Reports pass/fail per test scenario

### 6.5 Output Parsing

| Output Pattern | Meaning |
|---|---|
| Contains `passed` and `0 failed` | All tests passed |
| Contains `FAILED` | Test failure — extract test name and expected vs actual |
| Contains `ContainerLaunchException` | Testcontainer failed to start — check Docker |
| Contains `ActionTimeoutException` | No response received within timeout |

### 6.6 Integration with Verify Loop

Test results feed into the verify loop (`camel-verify/guides/verify-loop.md` Phase 2). Test failures are classified using `camel-verify/guides/error-taxonomy.md` (Test Errors section) and routed to the appropriate fix target.
