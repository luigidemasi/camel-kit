## Nested EIP Patterns

### Split with Aggregate (Scatter-Gather)

```yaml
- split:
    simple: "${body.items}"
    aggregationStrategy: "#itemAggregator"
    steps:
      - setHeader:
          name: itemId
          simple: "${body.productId}"
      - enrich:
          uri: direct:get-inventory
          aggregationStrategy: "#inventoryEnricher"
      - transform:
          simple: "${body}"
# After split completes, body contains aggregated result
- to:
    uri: direct:finalize-order
```

### Choice Inside Split

```yaml
- split:
    simple: "${body.items}"
    steps:
      - choice:
          when:
            - simple: "${body.type} == 'digital'"
              steps:
                - to:
                    uri: direct:process-digital
            - simple: "${body.type} == 'physical'"
              steps:
                - to:
                    uri: direct:process-physical
          otherwise:
            steps:
              - log:
                  message: "Unknown item type: ${body.type}"
```

### Try-Catch-Finally (doTry)

```yaml
- doTry:
    steps:
      - to:
          uri: http:external-service/api
      - transform:
          simple: "Success: ${body}"
    doCatch:
      - exception:
          - java.net.SocketTimeoutException
          - java.net.ConnectException
        steps:
          - log:
              message: "Connection failed, using fallback"
              loggingLevel: WARN
          - setBody:
              constant: '{"status": "fallback"}'
    doFinally:
      steps:
        - log:
            message: "Request completed"
```

## Expression Languages

### Simple Language

```yaml
# Property access
simple: "${body.customer.name}"
simple: "${header.correlationId}"
simple: "${exchangeProperty.batchId}"

# Comparisons
simple: "${body.amount} > 100"
simple: "${header.priority} == 'high'"
simple: "${body.status} != null"

# Logical operators
simple: "${body.amount} > 100 && ${body.priority} == 'high'"

# String operations
simple: "${body.name} contains 'test'"
simple: "${body.email} regex '^[a-z]+@.*$'"

# Date/time
simple: "${date:now:yyyy-MM-dd}"
```

### JSONPath

```yaml
jsonpath: "$.customer.name"
jsonpath: "$.items[0].productId"
jsonpath: "$.items[?(@.quantity > 5)]"
jsonpath: "$.items.length()"
```

### JQ (JSON Processing)

```yaml
jq: '{orderId: .id, customerName: .customer.name}'
jq: '.items | map(select(.inStock == true))'
jq: '.items | map(.price * .quantity) | add'
```

### XPath (XML)

```yaml
xpath: "/order/customer/name/text()"
xpath:
  expression: "//ns:order/ns:id"
  namespaces:
    ns: "http://example.com/orders"
```

## Environment Variables and Placeholders

### Camel Property Placeholders

```yaml
from:
  uri: kafka:orders
  parameters:
    brokers: "{{KAFKA_BROKERS}}"
    groupId: "{{CONSUMER_GROUP:default-group}}"  # With default value
```

### Environment Variables in Expressions

```yaml
- setHeader:
    name: environment
    simple: "${env:ENVIRONMENT:development}"
```

## Complete Route Example

Source: Kafka → Unmarshal JSON → Filter → Split → Enrich (circuit breaker) → Aggregate → Persist to DB → DLQ error handling.

```yaml
# Generated by camel-kit
# Camel Version: {CAMEL_MAIN_VERSION}

- route:
    id: order-ingestion
    description: >
      Receive orders from Kafka, filter low-value orders,
      process items with inventory enrichment, and persist to database.

    errorHandler:
      deadLetterChannel:
        deadLetterUri: kafka:orders-dlq
        redeliveryPolicy:
          maximumRedeliveries: 3
          redeliveryDelay: 1000
          backOffMultiplier: 2
          useExponentialBackOff: true

    from:
      uri: kafka:orders
      parameters:
        brokers: "{{KAFKA_BROKERS}}"
        groupId: order-processor
        autoOffsetReset: earliest
      steps:
        - unmarshal:
            json:
              unmarshalType: com.example.Order
        - filter:
            simple: "${body.totalAmount} >= 50"
            steps:
              - split:
                  simple: "${body.items}"
                  aggregationStrategy: "#orderItemsAggregator"
                  steps:
                    - circuitBreaker:
                        resilience4jConfiguration:
                          failureRateThreshold: 50
                          waitDurationInOpenState: 10000
                        steps:
                          - enrich:
                              uri: direct:inventory-lookup
                              aggregationStrategy: "#inventoryEnricher"
                        onFallback:
                          steps:
                            - log:
                                message: "Inventory service unavailable"
                                loggingLevel: WARN
              - to:
                  uri: jpa:com.example.Order
                  parameters:
                    persistenceUnit: orders

- route:
    id: inventory-lookup
    description: Lookup inventory for an order item
    from:
      uri: direct:inventory-lookup
      steps:
        - setHeader:
            name: productId
            simple: "${body.productId}"
        - to:
            uri: http:inventory-service/api/products/${header.productId}
        - unmarshal:
            json:
              unmarshalType: com.example.Inventory
```

## Kaoto Visual Tips

- Keep routes linear when possible — complex branching is harder to read
- Use descriptive route IDs — they appear as labels in the canvas
- Limit nesting depth to ≤3 levels
- Break complex routes into sub-routes connected via `direct:`

| YAML Step | Kaoto Node |
|-----------|------------|
| `from:` | Source node (green) |
| `to:` | Sink/endpoint node (blue) |
| `filter:` | Diamond shape (conditional) |
| `choice:` | Diamond with branches |
| `split:` | Fork symbol |
| `aggregate:` | Join symbol |
