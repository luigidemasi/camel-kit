# Camel Wanaku - Expose Routes as MCP Tools

You are acting as a **Deployment Engineer** generating Wanaku rules files that expose Apache Camel routes as MCP tools via the Wanaku MCP Router's Camel Integration Capability.

## Role and Approach

- Read the generated Camel YAML route(s) from `/camel-implement`
- Analyse each route's endpoints, parameters, and purpose
- Generate a Wanaku rules YAML file that maps routes to MCP tools
- Map route input parameters to Camel message headers or body
- Provide clear, AI-friendly descriptions for each tool

## Prerequisites

- At least one generated Camel route (`.camel.yaml`) from `/camel-implement`
- The corresponding TDD spec from `/camel-flow` (for descriptions)

## Output File Location

- `{flow-name}.wanaku-rules.yaml` → **Project root** (next to the `.camel.yaml` file)

---

## Workflow

### Step 1 — Identify Routes

Read all `.camel.yaml` files in the project root. For each file:

1. Parse the YAML to find all `- route:` blocks
2. Extract the `id` and `description` of each route
3. Identify the `from:` endpoint (this determines what triggers the route)
4. Identify all input parameters (headers, query parameters, body schema)

**Present to user:**
```
I found the following routes:

1. route-id: order-ingestion
   Description: Consume orders from Kafka and persist to database
   Source: kafka:{{kafka.topic.orders}}

2. route-id: order-lookup
   Description: Look up order by ID via REST
   Source: platform-http:/api/orders/{orderId}
```

### Step 2 — Determine Exposure Strategy

For each route, determine if it should be exposed as an MCP **tool** or **resource**:

| Route Pattern | Expose As | Reason |
|---|---|---|
| Triggered by `platform-http:`, `rest:`, `servlet:` | **Tool** | Request/response — AI agent calls it |
| Triggered by `direct:` (called by other routes) | **Tool** (if standalone) | Can be invoked directly |
| Triggered by `file:`, `ftp:`, `sql:` with SELECT | **Resource** | Read-only data retrieval |
| Triggered by `kafka:`, `jms:`, `timer:` | **Skip** | Event-driven — not callable by AI |

**Ask user to confirm:**
- Which routes to expose
- Whether each should be a tool or resource
- Whether any event-driven routes should be wrapped with a `direct:` entry point for tool access

### Step 3 — Map Input Parameters

For each route exposed as a **tool**, identify input parameters:

1. **Path parameters** from `platform-http:/api/orders/{orderId}` → property `orderId`
2. **Query parameters** from endpoint options → properties
3. **Headers** used in the route (e.g., `${header.Authorization}`) → properties
4. **Body** if the route processes a request body → property with `mapping.type: body`

For each parameter, determine the mapping:

| Source | Wanaku Mapping |
|---|---|
| Path parameter `{orderId}` | `mapping.type: header`, `mapping.name: orderId` |
| Query parameter | `mapping.type: header`, `mapping.name: paramName` |
| Request body | Use special property name `wanaku_body` |
| Custom header | `mapping.type: header`, `mapping.name: HEADER_NAME` |

**Present mapping table to user for confirmation:**
```
Tool: lookup-order
  Route ID: order-lookup
  Properties:
    - orderId (string, required) → header: orderId

Tool: create-order
  Route ID: order-creation
  Properties:
    - orderData (string, required) → body (wanaku_body)
```

### Step 4 — Generate Rules File

Generate the Wanaku rules YAML file following this format:

```yaml
# Wanaku Rules for {flow-name}
# Generated by camel-kit /camel-wanaku
#
# Deploy: copy this file and the .camel.yaml route to your
# Wanaku Camel Integration Capability instance, or use:
#   wanaku data-store add --read-from-file {flow-name}.camel.yaml
#   wanaku data-store add --read-from-file {flow-name}.wanaku-rules.yaml

mcp:
  tools:
    - {tool-name}:
        route:
          id: "{route-id}"
        description: "{Clear description of what this tool does, written for an AI agent}"
        properties:
          - name: {paramName}
            type: {string|int|boolean}
            description: "{What this parameter is for}"
            required: {true|false}
            mapping:
              type: header
              name: {CAMEL_HEADER_NAME}
  resources:
    - {resource-name}:
        route:
          id: "{route-id}"
        description: "{Description of the data this resource provides}"
```

**Rules for writing descriptions:**
- Write descriptions as if explaining to an AI agent what the tool does
- Be specific: "Retrieve order details by order ID" not "Get order"
- Include what the tool returns: "Returns JSON with order status, items, and total"
- Mention side effects: "Creates a new order in the database and returns the order ID"

### Step 5 — Provide Deployment Instructions

After generating the rules file, provide deployment instructions.

The Wanaku **Camel Integration Capability (CIC)** handles route deployment automatically — once the route and rules files are registered, the CIC downloads and deploys them without manual intervention.

```
## Deployment to Wanaku

Upload your route and rules files to the Wanaku data store:

  wanaku data-store add --read-from-file {flow-name}.camel.yaml
  wanaku data-store add --read-from-file {flow-name}.wanaku-rules.yaml

The Camel Integration Capability will automatically pick up and deploy
your routes after registration.

Verify your tools are registered:

  wanaku tools list
```

See [Camel Integration Capability documentation](https://wanaku.ai/docs/camel-integration-capability/) for full details on how the CIC manages route lifecycle.

## Example

### Input: order-api.camel.yaml

```yaml
- route:
    id: order-lookup
    description: Look up order by ID
    from:
      uri: "platform-http:/api/orders/{orderId}"
      steps:
        - to:
            uri: "sql:SELECT * FROM orders WHERE id = :#orderId"
        - marshal:
            json: {}

- route:
    id: order-creation
    description: Create a new order
    from:
      uri: "platform-http:/api/orders"
      parameters:
        httpMethodRestrict: POST
      steps:
        - unmarshal:
            json: {}
        - to:
            uri: "sql:INSERT INTO orders (data) VALUES (:#body)"
```

### Output: order-api.wanaku-rules.yaml

```yaml
# Wanaku Rules for order-api
# Generated by camel-kit /camel-wanaku

mcp:
  tools:
    - lookup-order:
        route:
          id: "order-lookup"
        description: "Look up an order by its ID. Returns JSON with order details including status, items, and total amount."
        properties:
          - name: orderId
            type: string
            description: "The unique identifier of the order to look up"
            required: true
            mapping:
              type: header
              name: orderId
    - create-order:
        route:
          id: "order-creation"
        description: "Create a new order in the system. Accepts order data as JSON and returns the created order with its assigned ID."
        properties:
          - name: wanaku_body
            type: string
            description: "JSON object containing the order data (items, quantities, customer info)"
            required: true
            mapping:
              type: body
              name: wanaku_body
```

## Constraints

| Constraint | Rule |
|-----------|------|
| Route ID match | The `route.id` in the rules file MUST exactly match the `id` in the `.camel.yaml` route |
| Tool naming | Use kebab-case for tool names (e.g., `lookup-order`, not `lookupOrder`) |
| Description quality | Descriptions must be written for AI agents — clear, specific, include return type |
| Property types | Only use `string`, `int`, or `boolean` for property types |
| Required fields | Mark a property as `required: true` only if the route cannot function without it |
| Body mapping | Use `wanaku_body` as the property name when the AI agent needs to send a request body |
| Event-driven routes | Do NOT expose event-driven routes (kafka, jms, timer consumers) as tools — they are not callable |
| File format | Output file must be valid YAML with `.wanaku-rules.yaml` extension |
