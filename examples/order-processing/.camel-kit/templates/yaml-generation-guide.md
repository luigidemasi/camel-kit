# Camel YAML DSL Generation Guide

This guide defines the transformation rules for converting camel-kit route specifications into valid Apache Camel YAML DSL that is compatible with Kaoto and `camel run`.

---

## Kaoto Compatibility Requirements

The generated YAML **MUST** be loadable and easy to render in [Kaoto](https://kaoto.io/), the visual integration designer for Apache Camel. Follow these requirements:

### 1. Use Standard Camel YAML DSL Format

Kaoto expects the official Apache Camel YAML DSL format. Always use:

```yaml
- route:
    id: route-id
    from:
      uri: component:path
      steps:
        - step1
        - step2
```

**NOT** alternative formats like:
```yaml
# ❌ Wrong - Kaoto won't render this correctly
routes:
  - id: route-id
    from: component:path
```

### 2. Use `steps:` Array Format (Not Inline)

Kaoto renders each step as a visual node. Always use the array format:

```yaml
# ✅ Correct - Kaoto will render each step as a node
steps:
  - unmarshal:
      json: {}
  - filter:
      simple: "${body.active}"
  - to:
      uri: kafka:output
```

**NOT** inline format:
```yaml
# ❌ Wrong - Harder to render visually
steps:
  - unmarshal: { json: {} }
  - to: kafka:output
```

### 3. Use Explicit `uri:` and `parameters:` Structure

Kaoto parses URIs and parameters separately for visual editing:

```yaml
# ✅ Correct - Kaoto can edit parameters visually
from:
  uri: kafka:orders
  parameters:
    brokers: "{{KAFKA_BROKERS}}"
    groupId: order-processor
```

**NOT** query string format:
```yaml
# ⚠️ Works but harder to edit in Kaoto
from:
  uri: kafka:orders?brokers={{KAFKA_BROKERS}}&groupId=order-processor
```

### 4. Use Object Format for EIPs (Not Shorthand)

Kaoto displays EIP properties in the visual editor:

```yaml
# ✅ Correct - Kaoto shows all properties
- filter:
    simple: "${body.amount} > 100"
    steps:
      - to:
          uri: direct:process
```

**NOT** shorthand:
```yaml
# ❌ Wrong - Kaoto may not render correctly
- filter:
    expression: "${body.amount} > 100"
```

### 5. Include Route Metadata

Kaoto displays route metadata in the canvas:

```yaml
- route:
    id: order-ingestion              # Required - shown in Kaoto
    description: Process orders...    # Shown as tooltip/description
    from:
      ...
```

### 6. Use Standard EIP Names

Kaoto recognizes standard EIP names. Use:

| Correct (Kaoto) | Avoid |
|-----------------|-------|
| `filter` | `when` (standalone) |
| `choice` with `when`/`otherwise` | `if`/`else` |
| `split` | `foreach` |
| `aggregate` | `collect` |
| `to` | `send` |
| `setHeader` | `header` |
| `setBody` | `body` |
| `transform` | `map` |

### 7. Nested Steps Structure

For EIPs with nested processing, always use `steps:` array:

```yaml
# ✅ Correct - Kaoto renders nested flow
- split:
    simple: "${body.items}"
    steps:                          # Nested steps inside split
      - log:
          message: "Processing ${body}"
      - to:
          uri: direct:process-item
```

### 8. Error Handler at Route Level

Place error handlers at route level for Kaoto to display them:

```yaml
- route:
    id: my-route

    errorHandler:                   # Kaoto shows error handling config
      deadLetterChannel:
        deadLetterUri: kafka:dlq

    from:
      uri: kafka:input
      steps:
        - to:
            uri: jpa:Order
```

### 9. Comments for Documentation

Kaoto preserves YAML comments. Use them for documentation:

```yaml
- route:
    id: order-ingestion

    from:
      uri: kafka:orders
      steps:
        # Deserialize JSON payload
        - unmarshal:
            json:
              unmarshalType: com.example.Order

        # Filter low-value orders
        - filter:
            simple: "${body.totalAmount} >= 50"
```

### 10. File Header

Include metadata header for context:

```yaml
# Generated by camel-kit
# Project: my-integration
# Camel Version: 4.17.0
# Generated: 2024-01-15T10:30:00Z
#
# Open in Kaoto: https://kaoto.io
# Run with: camel run routes.camel.yaml

- route:
    id: ...
```

## Basic Route Structure

### Single Route

```yaml
- route:
    id: route-id
    description: Route description text

    from:
      uri: component:destination
      parameters:
        option1: value1
        option2: value2
      steps:
        - step1
        - step2
        - to:
            uri: sink:destination
```

### Multiple Routes

```yaml
- route:
    id: first-route
    from:
      uri: kafka:orders
      steps:
        - to:
            uri: direct:process

- route:
    id: second-route
    from:
      uri: direct:process
      steps:
        - to:
            uri: jpa:Order
```

## Source Transformation

### Component Source

**Spec:**
```markdown
## Source
| Property | Value |
|----------|-------|
| Type | Component |
| Component | kafka |
| Topic | orders |
| Brokers | {{KAFKA_BROKERS}} |
| Group ID | order-processor |
```

**YAML:**
```yaml
from:
  uri: kafka:orders
  parameters:
    brokers: "{{KAFKA_BROKERS}}"
    groupId: order-processor
```

### Kamelet Source

**Spec:**
```markdown
## Source
| Property | Value |
|----------|-------|
| Type | Kamelet |
| Kamelet | kafka-source |
| bootstrapServers | {{KAFKA_BROKERS}} |
| topic | orders |
```

**YAML:**
```yaml
from:
  uri: kamelet:kafka-source
  parameters:
    bootstrapServers: "{{KAFKA_BROKERS}}"
    topic: orders
```

**Spec:**

```markdown
| Property | Value |

```

```yaml
from:
  uri: direct:process-order
```

## EIP Transformations

### Filter

**Spec:**
```markdown
### Step 1: Filter
- **EIP**: Filter
- **Condition**: `${body.totalAmount} >= 50`
- **Purpose**: Remove orders under $50
```

**YAML (simple expression):**
```yaml
steps:
  - filter:
      simple: "${body.totalAmount} >= 50"
```

**YAML (with nested steps):**
```yaml
steps:
  - filter:
      simple: "${body.status} == 'active'"
      steps:
        - log:
            message: "Processing active order"
        - to:
            uri: direct:process
```

### Choice (Content-Based Router)

**Spec:**
```markdown
### Step 2: Route by Priority
- **EIP**: Choice
- **Conditions**:
  - priority == 'high' → direct:fast-track
  - priority == 'low' → direct:batch
  - otherwise → direct:standard
```

**YAML:**
```yaml
steps:
  - choice:
      when:
        - simple: "${body.priority} == 'high'"
          steps:
            - to:
                uri: direct:fast-track
        - simple: "${body.priority} == 'low'"
          steps:
            - to:
                uri: direct:batch
      otherwise:
        steps:
          - to:
              uri: direct:standard
```

### Split

**Spec:**
```markdown
### Step 3: Split
- **EIP**: Split
- **Expression**: `${body.items}`
- **Parallel**: false
```

**YAML (simple split):**
```yaml
steps:
  - split:
      simple: "${body.items}"
      steps:
        - log:
            message: "Processing item: ${body}"
        - to:
            uri: direct:process-item
```

**YAML (with streaming and parallel processing):**
```yaml
steps:
  - split:
      tokenize:
        token: "\n"
      streaming: true
      parallelProcessing: true
      steps:
        - to:
            uri: direct:process-line
```

**YAML (with JSONPath for arrays):**
```yaml
steps:
  - split:
      jsonpath: "$.items[*]"
      steps:
        - to:
            uri: direct:process-item
```

### Aggregate

**Spec:**
```markdown
### Step 4: Aggregate
- **EIP**: Aggregate
- **Correlation**: `${header.orderId}`
- **Completion**: Size = 10
- **Strategy**: groupedBodyStrategy
```

**YAML (size-based completion):**
```yaml
steps:
  - aggregate:
      correlationExpression:
        simple: "${header.orderId}"
      completionSize: 10
      aggregationStrategy: "#groupedBodyStrategy"
      steps:
        - to:
            uri: direct:process-batch
```

**YAML (timeout-based completion):**
```yaml
steps:
  - aggregate:
      correlationExpression:
        simple: "${header.batchId}"
      completionTimeout: 5000
      aggregationStrategy: "#myAggregator"
      steps:
        - to:
            uri: direct:complete-batch
```

**YAML (predicate-based completion):**
```yaml
steps:
  - aggregate:
      correlationExpression:
        simple: "${header.groupId}"
      completionPredicate:
        simple: "${body.size()} >= 100"
      steps:
        - to:
            uri: direct:flush
```

### Enrich

**Spec:**
```markdown
### Step 5: Enrich
- **EIP**: Enrich
- **Endpoint**: direct:customer-lookup
- **Strategy**: customerEnricher
```

**YAML (enrich with aggregation strategy):**
```yaml
steps:
  - enrich:
      uri: direct:customer-lookup
      aggregationStrategy: "#customerEnricher"
```

**YAML (poll enrich from file):**
```yaml
steps:
  - pollEnrich:
      uri: file:data/lookup?fileName=${header.lookupFile}
      timeout: 5000
      aggregationStrategy: "#fileEnricher"
```

### Transform / SetBody

**Spec:**
```markdown
### Step 6: Transform
- **EIP**: Transform
- **Expression**: Create response object
```

**YAML (simple expression):**
```yaml
steps:
  - setBody:
      simple: "Order ${body.orderId} processed successfully"
```

**YAML (constant):**
```yaml
steps:
  - setBody:
      constant: "OK"
```

**YAML (using JQ for JSON transformation):**
```yaml
steps:
  - transform:
      jq: '{id: .orderId, status: "processed", timestamp: now}'
```

**YAML (using Groovy):**
```yaml
steps:
  - transform:
      groovy: |
        [
          id: body.orderId,
          customer: body.customerName,
          total: body.items.sum { it.price * it.quantity }
        ]
```

### SetHeader

**YAML:**
```yaml
steps:
  - setHeader:
      name: correlationId
      simple: "${exchangeId}"
  - setHeader:
      name: processedAt
      simple: "${date:now:yyyy-MM-dd'T'HH:mm:ss}"
```

### Log

**YAML:**
```yaml
steps:
  - log:
      message: "Processing order ${body.orderId}"
      loggingLevel: INFO
      logName: order.processor
```

### To (Send to Endpoint)

**YAML (component):**
```yaml
steps:
  - to:
      uri: kafka:processed-orders
      parameters:
        brokers: "{{KAFKA_BROKERS}}"
```

**YAML (Kamelet sink):**
```yaml
steps:
  - to:
      uri: kamelet:kafka-sink
      parameters:
        bootstrapServers: "{{KAFKA_BROKERS}}"
        topic: processed-orders
```

**YAML (dynamic endpoint):**
```yaml
steps:
  - toD:
      uri: "${header.targetEndpoint}"
```

### Bean

**YAML:**
```yaml
steps:
  - bean:
      ref: orderProcessor
      method: processOrder
```

### Multicast

**YAML (send to multiple destinations):**
```yaml
steps:
  - multicast:
      parallelProcessing: true
      steps:
        - to:
            uri: kafka:audit-log
        - to:
            uri: direct:notification
        - to:
            uri: jpa:Order
```

### Recipient List (Dynamic Routing)

**YAML:**
```yaml
steps:
  - recipientList:
      simple: "${header.destinations}"
      delimiter: ","
      parallelProcessing: true
```

### Wire Tap (Fire and Forget Copy)

**YAML:**
```yaml
steps:
  - wireTap:
      uri: kafka:audit-events
  - to:
      uri: direct:continue-processing
```

### Validate

**YAML (with predicate):**
```yaml
steps:
  - validate:
      simple: "${body.orderId} != null"
```

**YAML (with JSON schema):**
```yaml
steps:
  - to:
      uri: json-validator:schemas/order.json
```

## Nested EIP Patterns

### Split with Aggregate (Scatter-Gather)

**Spec:**
```markdown
Split order items, process each, then reaggregate into single response.
```

**YAML:**
```yaml
steps:
  - split:
      simple: "${body.items}"
      aggregationStrategy: "#itemAggregator"
      steps:
        - setHeader:
            name: itemId
            simple: "${body.productId}"
        - enrich:
            uri: direct:get-inventory
            aggregationStrategy: "#inventoryEnricher"
        - transform:
            simple: "${body}"
  # After split completes, body contains aggregated result
  - to:
      uri: direct:finalize-order
```

### Choice Inside Split

**YAML:**
```yaml
steps:
  - split:
      simple: "${body.items}"
      steps:
        - choice:
            when:
              - simple: "${body.type} == 'digital'"
                steps:
                  - to:
                      uri: direct:process-digital
              - simple: "${body.type} == 'physical'"
                steps:
                  - to:
                      uri: direct:process-physical
            otherwise:
              steps:
                - log:
                    message: "Unknown item type: ${body.type}"
```

### Filter Inside Choice

**YAML:**
```yaml
steps:
  - choice:
      when:
        - simple: "${header.priority} == 'high'"
          steps:
            - filter:
                simple: "${body.value} > 1000"
                steps:
                  - to:
                      uri: direct:high-value-priority
            - to:
                uri: direct:priority-queue
      otherwise:
        steps:
          - to:
              uri: seda:standard-queue
```

### Try-Catch-Finally (doTry)

**YAML:**
```yaml
steps:
  - doTry:
      steps:
        - to:
            uri: http:external-service/api
        - transform:
            simple: "Success: ${body}"
      doCatch:
        - exception:
            - java.net.SocketTimeoutException
            - java.net.ConnectException
          steps:
            - log:
                message: "Connection failed, using fallback"
                loggingLevel: WARN
            - setBody:
                constant: '{"status": "fallback"}'
      doFinally:
        steps:
          - log:
              message: "Request completed"
```

## Error Handling

### Dead Letter Channel

**Spec:**
```markdown
## Error Handling
| Property | Value |
|----------|-------|
| Strategy | Dead Letter Channel |
| Endpoint | kafka:orders-dlq |
| Max Retries | 3 |
| Retry Delay | 1000 |
| Backoff Multiplier | 2 |
```

**YAML (route-level):**
```yaml
- route:
    id: order-ingestion

    errorHandler:
      deadLetterChannel:
        deadLetterUri: kafka:orders-dlq
        redeliveryPolicy:
          maximumRedeliveries: 3
          redeliveryDelay: 1000
          backOffMultiplier: 2
          useExponentialBackOff: true
          retryAttemptedLogLevel: WARN

    from:
      uri: kafka:orders
      steps:
        - to:
            uri: jpa:Order
```

### Default Error Handler with Retry

**YAML:**
```yaml
- route:
    id: my-route

    errorHandler:
      defaultErrorHandler:
        redeliveryPolicy:
          maximumRedeliveries: 5
          redeliveryDelay: 2000
          maximumRedeliveryDelay: 60000
          backOffMultiplier: 2
          useExponentialBackOff: true

    from:
      uri: direct:input
      steps:
        - to:
            uri: http:external-api
```

### onException (Type-Specific Handling)

**YAML:**
```yaml
- route:
    id: order-processor

    from:
      uri: kafka:orders
      steps:
        - onException:
            exception:
              - com.example.ValidationException
            handled: true
            steps:
              - log:
                  message: "Validation failed: ${exception.message}"
              - to:
                  uri: kafka:orders-invalid

        - onException:
            exception:
              - java.sql.SQLException
            maximumRedeliveries: 3
            redeliveryDelay: 5000
            handled: true
            steps:
              - to:
                  uri: kafka:orders-dlq

        # Main route logic
        - to:
            uri: bean:orderValidator
        - to:
            uri: jpa:Order
```

### Circuit Breaker (Resilience4j)

**YAML:**
```yaml
steps:
  - circuitBreaker:
      resilience4jConfiguration:
        failureRateThreshold: 50
        waitDurationInOpenState: 10000
        slidingWindowSize: 10
        minimumNumberOfCalls: 5
      steps:
        - to:
            uri: http:external-service/api
      onFallback:
        steps:
          - setBody:
              constant: '{"status": "service unavailable", "cached": true}'
          - log:
              message: "Circuit open, returning fallback"
```

## Complex Expression Patterns

### Simple Language

```yaml
# Property access
simple: "${body.customer.name}"

# Header access
simple: "${header.correlationId}"

# Exchange property
simple: "${exchangeProperty.batchId}"

# Comparisons
simple: "${body.amount} > 100"
simple: "${header.priority} == 'high'"
simple: "${body.status} != null"

# Logical operators
simple: "${body.amount} > 100 && ${body.priority} == 'high'"
simple: "${body.type} == 'A' || ${body.type} == 'B'"

# String operations
simple: "${body.name} contains 'test'"
simple: "${body.email} regex '^[a-z]+@.*$'"

# Null checks
simple: "${body.optional} != null"
simple: "${header.X-Custom-Header} == null"

# Date/time
simple: "${date:now:yyyy-MM-dd}"
simple: "${date:header.timestamp:yyyy-MM-dd'T'HH:mm:ss}"
```

### JSONPath

```yaml
# Extract field
jsonpath: "$.customer.name"

# Array access
jsonpath: "$.items[0].productId"

# Filter array
jsonpath: "$.items[?(@.quantity > 5)]"

# Aggregate
jsonpath: "$.items.length()"
```

### JQ (JSON Processing)

```yaml
# Transform structure
jq: '{orderId: .id, customerName: .customer.name}'

# Filter and map
jq: '.items | map(select(.inStock == true))'

# Calculate
jq: '.items | map(.price * .quantity) | add'
```

### XPath (XML)

```yaml
# Extract element
xpath: "/order/customer/name/text()"

# With namespace
xpath:
  expression: "//ns:order/ns:id"
  namespaces:
    ns: "http://example.com/orders"
```

## Complete Route Example

**Spec summary:**
- Source: Kafka topic "orders"
- Unmarshal JSON to Order class
- Filter orders >= $50
- Split by items
- Enrich with inventory data (circuit breaker)
- Aggregate back
- Persist to database
- Error handling: Dead Letter Channel

**Generated YAML:**

```yaml
# Generated by camel-kit
# Camel Version: 4.17.0
# Generated: 2024-01-15T10:30:00Z

- route:
    id: order-ingestion
    description: >
      Receive orders from Kafka, filter low-value orders,
      process items with inventory enrichment, and persist to database.

    errorHandler:
      deadLetterChannel:
        deadLetterUri: kafka:orders-dlq
        redeliveryPolicy:
          maximumRedeliveries: 3
          redeliveryDelay: 1000
          backOffMultiplier: 2
          useExponentialBackOff: true

    from:
      uri: kafka:orders
      parameters:
        brokers: "{{KAFKA_BROKERS}}"
        groupId: order-processor
        autoOffsetReset: earliest
      steps:
        # Unmarshal JSON
        - unmarshal:
            json:
              unmarshalType: com.example.Order

        # Filter low-value orders
        - filter:
            simple: "${body.totalAmount} >= 50"
            steps:
              # Split by items
              - split:
                  simple: "${body.items}"
                  aggregationStrategy: "#orderItemsAggregator"
                  steps:
                    # Enrich with inventory (circuit breaker protected)
                    - circuitBreaker:
                        resilience4jConfiguration:
                          failureRateThreshold: 50
                          waitDurationInOpenState: 10000
                        steps:
                          - enrich:
                              uri: direct:inventory-lookup
                              aggregationStrategy: "#inventoryEnricher"
                        onFallback:
                          steps:
                            - log:
                                message: "Inventory service unavailable"
                                loggingLevel: WARN

              # After split/aggregate completes
              - log:
                  message: "Persisting order ${body.orderId}"

              # Persist to database
              - to:
                  uri: jpa:com.example.Order
                  parameters:
                    persistenceUnit: orders

- route:
    id: inventory-lookup
    description: Lookup inventory for an order item

    from:
      uri: direct:inventory-lookup
      steps:
        - setHeader:
            name: productId
            simple: "${body.productId}"
        - to:
            uri: http:inventory-service/api/products/${header.productId}
        - unmarshal:
            json:
              unmarshalType: com.example.Inventory
```

## Kaoto Visual Rendering Tips

### Route Layout

Kaoto displays routes as a visual flow from left to right:

```
[Source] → [Step 1] → [Step 2] → [Step 3] → [Sink]
```

To ensure clear visualization:

1. **Keep routes linear when possible** - Complex branching is harder to read
2. **Use descriptive route IDs** - They appear as labels in the canvas
3. **Add descriptions** - Shown as tooltips on hover
4. **Limit nesting depth** - Deep nesting (>3 levels) is hard to visualize

### Step Representation

Each YAML step becomes a visual node in Kaoto:

| YAML Step | Kaoto Node |
|-----------|------------|
| `from:` | Source node (green) |
| `to:` | Sink/endpoint node (blue) |
| `filter:` | Diamond shape (conditional) |
| `choice:` | Diamond with branches |
| `split:` | Fork symbol |
| `aggregate:` | Join symbol |
| `transform:` / `setBody:` | Rectangle |
| `log:` | Rectangle with log icon |

### Improving Visual Clarity

**Break complex routes into sub-routes:**

Instead of:
```yaml
- route:
    id: complex-route
    from:
      uri: kafka:input
      steps:
        - unmarshal: ...
        - filter: ...
        - split: ...
        - choice: ...
        - aggregate: ...
        - transform: ...
        - to: kafka:output
```

Better for Kaoto:
```yaml
- route:
    id: ingest-orders
    from:
      uri: kafka:input
      steps:
        - unmarshal: ...
        - filter: ...
        - to:
            uri: direct:process-orders

- route:
    id: process-orders
    from:
      uri: direct:process-orders
      steps:
        - split: ...
        - to:
            uri: direct:finalize

- route:
    id: finalize-orders
    from:
      uri: direct:finalize
      steps:
        - aggregate: ...
        - to:
            uri: kafka:output
```

After generating YAML:

1. Open [Kaoto Web](https://kaoto.io/) or Kaoto VS Code extension
2. Click "Import" or drag-drop the `.camel.yaml` file
3. Verify all routes render correctly
4. Check that you can click on nodes and see/edit properties
5. Verify error handlers are shown

## Output File Structure

### Single File (Default)

```
my-integration/
├── routes.camel.yaml           # Generated routes (project root)
└── .camel-kit/
    └── routes/                 # Route specifications
```

### Split Files (--split option)

```
my-integration/
├── routes.camel.yaml           # All routes combined
├── order-ingestion.camel.yaml  # Individual route
├── inventory-lookup.camel.yaml # Individual route
└── .camel-kit/
    └── routes/
```

### Pipe Format (--pipe option)

```yaml
apiVersion: camel.apache.org/v1
kind: Pipe
metadata:
```
